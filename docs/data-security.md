# 데이터와 보안 원칙

## 원문과 공개 저장소

- 실제 기사·댓글 원문과 `data/` 실행 산출물은 Git에 포함하지 않습니다.
- `analysis/`에는 원문이 아닌 데이터셋 명세, 집계 profile과 공개 가능한 검증 로그만 둡니다.
- 실행 로그에는 텍스트 payload, API key, DSN과 사용자 식별값을 기록하지 않습니다.
- 원문 예시는 공개 가능한 합성 이벤트만 사용합니다.

## 개인정보와 텍스트 처리

- Reddit 작성자와 사용자 식별값은 공통 이벤트에 저장하지 않습니다.
- 이메일·전화번호 등 PII 패턴이 감지된 텍스트는 `quarantine`으로 분리합니다.
- 외부 LLM에는 품질 검사와 비식별화 정책을 통과한 텍스트만 전달합니다.
- 품질 flag는 악성 사용자를 확정하는 값이 아니라 후속 처리 정책을 위한 관측값입니다.

## 자격 증명

- `.env`, API key, 실제 비밀번호, webhook과 운영 DSN은 커밋하지 않습니다.
- Docker Compose의 PostgreSQL 계정은 로컬 개발 전용이며 운영 환경에서 재사용하지 않습니다.
- 운영 환경에서는 환경 변수 또는 secret manager로 자격 증명을 주입합니다.
- 로그와 예외 메시지에는 DSN 전체 문자열을 남기지 않습니다.

## 보존과 삭제

- Kafka `raw-text`와 DLQ의 보존 기간은 목적에 맞게 분리합니다.
- PostgreSQL 원본·정제 데이터의 보존 기간과 삭제 요청 절차는 운영 전 확정합니다.
- checkpoint와 batch commit은 데이터 재처리 기준이므로 원본 데이터와 별도의 수명 주기를 갖습니다.
- 테스트 volume을 삭제할 때는 대상 환경과 복구 가능성을 확인합니다.

## 외부 데이터와 모델

- 기사 전문 수집은 저작권, 이용약관과 robots 정책을 검토한 뒤 선택적으로 확장합니다.
- 데이터셋 페이지와 이용 조건의 확인 날짜를 명세에 기록합니다.
- LLM prompt·응답 원문 저장 여부는 Langfuse 도입 결정과 함께 별도 ADR로 확정합니다.

세부 품질 규칙은 [텍스트 품질·안전 규칙](../analysis/quality/text-quality-rules.md), 출처별 이용 범위는 [데이터셋 명세](../analysis/README.md)를 참고합니다.
